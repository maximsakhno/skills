# Чистый Python

Свод для Python-кода, который агент пишет, правит, рефакторит или ревьюит. Это дополнение к скиллу clean-code: общие правила об именах, размере функций, ответственности, дублировании и комментариях берутся оттуда, здесь — только их Python-форма и то, чего нет в других языках.

Главный принцип: опираться на возможности языка и stdlib той версии, что стоит в проекте, — протоколы, генераторы, dataclass, contextlib, itertools, — а не переносить ручные конструкции из других языков. Тип — проверяемое тайпчекером сообщение о том, какие значения допустимы: выбирать самый узкий тип, при котором недопустимое состояние нельзя записать.

## 1. Версия Python проекта

- **Узнать нижнюю версию Python до того, как писать код.** Искать по порядку: `requires-python` в `pyproject.toml`, `.python-version`, `target-version` в настройках ruff, `python_version` в mypy, образ в `Dockerfile`, матрица версий в CI. Решает нижняя граница `requires-python`, а не локальный интерпретатор. Если версии нигде нет — сказать о допущении одной строкой.
- **Писать с возможностями именно этой версии — не ниже и не выше.** Ниже — устаревшие идиомы, выше — код не запустится. Пометку «(3.11+)» в правилах ниже читать как условие: на более старой версии брать указанную замену.
- **Новые конструкции `typing` на старой версии брать из `typing_extensions`, если он уже в зависимостях.** Синтаксис (`match`, `type`, `class Box[T]`, `except*`) не бэкпортируется. Тайпчекеры отстают от рантайма: для PEP 695 и новее проверять, что их поддерживает версия mypy или pyright в проекте.
- **Осовременивать код, который всё равно трогаешь, а при ревью отмечать устаревшее.** Массовую замену синтаксиса в нетронутых файлах не делать без просьбы.

| Устаревшее | Современное | С версии |
|---|---|---|
| `List[int]`, `Dict[str, int]`, `typing.Iterable` | `list[int]`, `dict[str, int]`, `collections.abc.Iterable` | 3.9 |
| `Optional[X]`, `Union[A, B]` | `X \| None`, `A \| B` | 3.10 |
| цепочка `isinstance` и `len` для разбора структуры | `match` | 3.10 |
| `zip(xs, xs[1:])`; `assert len(a) == len(b)` перед `zip` | `pairwise(xs)`; `zip(a, b, strict=True)` | 3.10 |
| `def copy(self: T) -> T` с `TypeVar(bound=...)` | `def copy(self) -> Self` | 3.11 |
| `class Status(str, Enum)`; `datetime.utcnow()` | `class Status(StrEnum)`; `datetime.now(UTC)` | 3.11 |
| `T = TypeVar("T")`, `class Box(Generic[T])`, `X: TypeAlias = ...` | `class Box[T]:`, `def first[T](xs: Sequence[T]) -> T`, `type X = ...` | 3.12 |
| опечатка в имени переопределённого метода проходит молча | `@override` | 3.12 |
| `[xs[i:i + n] for i in range(0, len(xs), n)]` | `batched(xs, n)` | 3.12 |
| `TypeGuard`; `dataclasses.replace(p, x=1)` | `TypeIs`; `copy.replace(p, x=1)` | 3.13 |
| `def f(x: "Later")`, `from __future__ import annotations` | `def f(x: Later)` | 3.14 |

Полная таблица по версиям 3.8–3.15, устаревшие и удалённые API — в `versions.md`.

## 2. Выражения и идиомы

- **С `None` и сентинелами сравнивать через `is`, булевы значения — без оператора, остальное — через `==`.** `==` можно перегрузить, а `is` для чисел и строк зависит от кэша интерпретатора (он хранит целые от −5 до 256). Плохо: `if x == None`, `if done == True`, `if code is 404` → хорошо: `if x is None`, `if done:`, `if code == 404`.
- **Проверять отсутствие через `is None`, а не через ложность, если `0`, `""` или `[]` — законные значения.** `limit = limit or DEFAULT` подменит и `0`. Хорошо: `if limit is None: limit = DEFAULT`.
- **Проверять диапазон цепочкой, варианты — через `in`.** `0 <= i < n`, `status in {Status.NEW, Status.PAID}`. Не сцеплять `!=` и разные операторы: `a != b != c` истинно при `a == c`.
- **Тернарный оператор — только короткий, на одной строке и не вложенный.** Не писать `cond and a or b`: вернёт `b`, когда `a` ложно. Вложенный тернарный — `if/elif`.
- **Использовать `:=`, когда он убирает повторный вызов или лишнюю строку.** `if (match := PATTERN.search(line)):`, `while chunk := stream.read(CHUNK_SIZE):`, фильтр в comprehension. В составе выражения — в скобках.
- **Применять `match` для разбора неоднородных данных, а не вместо `if/elif` по значениям.** Голое имя в `case` — захват, совпадает со всем: константы только через точку (`case Color.RED:`), тип — со скобками (`case float():`). Строки не совпадают с шаблоном последовательности, итераторы — ни с каким. Всегда заканчивать `case _:` с ошибкой — иначе несовпадение молча пропускается.

  ```python
  # плохо
  match status:
      case OK:  # захват в переменную OK, а не сравнение
          ...
  # хорошо
  match event:
      case {"type": "login", "user": str(user_id)}:
          return Login(user_id=user_id)
      case {"type": "logout", "user": str(user_id)}:
          return Logout(user_id=user_id)
      case _:
          raise ValueError(f"unknown event: {event!r}")
  ```

- **Форматировать f-строками.** `%` и `str.format` многословны и ломаются при перестановке аргументов. Для отладочного вывода — `{value!r}` и `{value=}`: `str` скрывает разницу между `5` и `'5'`. В логировании f-строки не нужны — значения уходят в `extra`.
- **Собирать строку из многих частей через `"".join(parts)`, а не `+=` в цикле.** Одиночная конкатенация и f-строка — нормально.
- **Не ставить висячую запятую и не склеивать строки неявно в литералах.** `total = compute(x),` — это кортеж. `["a" "b", "c"]` из-за пропущенной запятой молча даёт два элемента вместо трёх. Одноэлементный кортеж — всегда в скобках: `(item,)`.
- **Пути строить через `pathlib.Path` и `/`, файлы открывать в `with` и с явной кодировкой.** `Path(root) / "data" / name`, `open(path, encoding="utf-8")` (до 3.15 кодировка по умолчанию зависит от ОС). Кодировать и декодировать `bytes` только на границе программы, внутри — `str`. Регулярные выражения — в raw-строках: `r"\d+"`.
- **Пользовательский текст сравнивать после нормализации.** `unicodedata.normalize("NFC", s)` перед сохранением и сравнением, без учёта регистра — `casefold()`, а не `lower()`. Ошибки кодирования не глушить `errors="ignore"`.
- **Деньги считать в `Decimal`, созданном из строки, float сравнивать с допуском.** `Decimal("1.45")`, а не `Decimal(1.45)`; округлять `quantize(Decimal("0.01"), rounding=ROUND_HALF_UP)`. `0.1 + 0.2 == 0.3` ложно — `math.isclose`. Последовательность float считать как `start + step * i`, а не накоплением `+= step`.
- **Время хранить с часовым поясом в UTC, в локальное переводить последним шагом.** `datetime.now(UTC)` (3.11; раньше — `timezone.utc`), зоны — `ZoneInfo("Europe/Moscow")`, не `pytz` и не `datetime.utcnow()`.
- **Не затенять встроенные имена и модули.** После `list = [...]` вызов `list(...)` падает; файл `random.py` в проекте перехватит `import random`. Частые жертвы: `id`, `type`, `input`, `hash`, `filter`, `format`, `sum`, `min`, `max`.
- **Помнить, что `bool` — подкласс `int`.** `isinstance(True, int)` истинно: проверка на целое без исключения `bool` пропустит флаги.
- **Не подставлять внешние данные в SQL, shell и HTML f-строкой; не использовать `eval`/`exec`.** SQL — параметры запроса, параметр с текстом запроса можно аннотировать `LiteralString` (3.11). Процессы — `subprocess.run([...], check=True, capture_output=True, text=True)` со списком аргументов, без `shell=True` и `os.popen`.

## 3. Коллекции и итерация

- **Обходить элементы напрямую, индекс брать из `enumerate`, параллельные последовательности — `zip(..., strict=True)`.** Плохо: `for i in range(len(items)): item = items[i]` → хорошо: `for i, item in enumerate(items):`. Обычный `zip` молча обрезает по короткому (`strict` — с 3.10).
- **Распаковывать вместо индексов.** `for rank, (name, score) in enumerate(results, 1):`, `head, *rest = rows`, `a, b = b, a`. Звёздочка всегда даёт `list` и читает итератор целиком. Глубокую вложенную распаковку не писать.
- **Писать comprehension вместо `map`/`filter` с lambda и держать в нём не больше двух частей.** Плохо: `list(map(lambda x: x * 2, filter(lambda x: x > 0, xs)))` → хорошо: `[x * 2 for x in xs if x > 0]`. Два `for`, `for` + `if` — предел; сложнее — цикл или функция-генератор. Comprehension в comprehension не вкладывать; плоский список — `chain.from_iterable(lists)` (3.15: `[*xs for xs in lists]`).
- **Список списков создавать comprehension, а не умножением.** `[[0] * width] * height` — одна и та же строка `height` раз. Хорошо: `[[0] * width for _ in range(height)]`.
- **В `any`/`all` передавать генератор, первый подходящий элемент брать через `next(..., default)`.** `all(is_valid(x) for x in xs)` выходит на первом `False`, list comprehension считает всё. `next((u for u in users if u.is_admin), None)` вместо `[...][0]`. `all([])` истинно — пустой вход проверять отдельно.
- **Не писать `else` после `for`/`while` и не читать переменную цикла после него.** `else` срабатывает, если не было `break`, — и на пустом входе, а переменной цикла на пустом входе нет. Хорошо: функция с ранним `return`.
- **Не обходить аргумент дважды, если он может быть итератором.** Второй проход по исчерпанному генератору молча пуст. Нужно несколько проходов — принимать `Collection`/`Sequence` или сразу материализовать `tuple(items)`; `Iterable` в аннотации обещает только один проход.
- **Не менять список, словарь или множество во время обхода.** Это `RuntimeError`, пропуск элементов или бесконечный цикл. Строить новую коллекцию (`[x for x in xs if keep(x)]`) или копить изменения и применять после цикла.
- **Вместо накопления списка через `append` писать генератор, вложенные генераторы собирать через `yield from`.** Генератор одноразовый. `send` и `throw` не использовать — состояние держать в классе. Ресурс (файл, блокировку) открывать снаружи генератора и передавать внутрь: `finally` недочитанного генератора выполнится только при сборке мусора.
- **Прежде чем писать сложный цикл, искать решение в `itertools`.** `pairwise`, `batched`, `islice`, `chain.from_iterable`, `takewhile`, `accumulate`, `product` вместо вложенных циклов, `groupby` (вход отсортирован по ключу). Бесконечные `count`/`cycle` ограничивать `islice`. Чтение до маркера — `iter(partial(f.read, 4096), b"")`.
- **Чужой словарь читать через `get`, своё состояние держать в `defaultdict` или `Counter`.** `counts[key] = counts.get(key, 0) + 1` — для чужого; `self._by_country = defaultdict(set)` и `Counter(words)` — для своего. `setdefault` не использовать: значение по умолчанию создаётся на каждый вызов. Слияние — `a | b` (3.9), дедупликация с порядком — `list(dict.fromkeys(items))`.
- **Заменять циклы операциями множеств.** Плохо: цикл со счётчиком совпадений → хорошо: `len(needles & haystack)`; `a.keys() & b.keys()` работает без преобразования. Методы (`set(a).intersection(b)`) принимают любой iterable, операторы — только множества.
- **Подбирать контейнер под операции.** Частые `in` — `set` или `dict`, а не `list` (иначе случайный O(n²)); очередь — `deque` (`list.pop(0)` — O(n)); «последние N» — `deque(maxlen=N)`; приоритетная очередь — `heapq`; поиск в отсортированном — `bisect`.
- **Сортировать по нескольким критериям ключом-кортежем и не сортировать чужой список на месте.** `sorted(tasks, key=lambda t: (-t.priority, t.name))`; `sorted` возвращает новый список, `list.sort` меняет аргумент вызывающего.

## 4. Функции и аргументы

- **Изменяемое или вычисляемое значение по умолчанию задавать через `None`.** `def f(items=[])` и `when=datetime.now()` вычисляются один раз при определении функции, и вызовы делят один объект.

  ```python
  # плохо
  def record(event: Event, tags: list[str] = [], when: datetime = datetime.now()) -> None: ...
  # хорошо
  def record(event: Event, tags: Sequence[str] = (), when: datetime | None = None) -> None:
      if when is None:
          when = datetime.now(UTC)
      ...
  ```

- **Флаги и необязательные параметры делать keyword-only, а параметры без осмысленного имени — positional-only.** Плохо: `divide(1.0, 0, False, True)` → хорошо: `def divide(a, b, /, *, ignore_zero_division=False)`. Новый параметр существующей функции — только keyword-only и с default: старые вызовы не сломаются, а у функций с `*args` новый позиционный параметр молча сдвинет аргументы.
- **Не доставать значения из `**kwargs` по ключу.** Плохо: `timeout = kwargs.get("timeout", 30)` → хорошо: `*, timeout: float = 30`. `*args, **kwargs` — только для прозрачных обёрток; открытый набор именованных параметров — `**kwargs: Unpack[Options]` с `TypedDict` (3.12).
- **Выбирать между `*args` и параметром-коллекцией по способу вызова.** Значения перечисляют в коде (`max(a, b)`) — `*args`; данные собираются во время работы (`sum(expenses)`) — одна коллекция. Генератор в `*args` материализуется целиком.
- **Не менять аргумент, если это не назначение функции, и копировать коллекцию, которую сохраняешь.** Плохо: `self._passengers = passengers` — `bus.drop(name)` удалит игрока из чужой команды → хорошо: `self._passengers = list(passengers)`. Функция, которая меняет объект на месте, возвращает `None`, как `list.sort`.
- **Возвращать значения одного типа, а больше двух-трёх значений — dataclass, не кортежем.** `minimum, maximum, average, median = stats(xs)` легко перепутать местами. `returns_int_or_str()` падает у вызывающего только иногда.
- **Отсутствие результата возвращать как `X | None`, ошибку — исключением, и не смешивать их.** «Не найдено» как обычный исход — `find_user(id) -> User | None`: тайпчекер заставит вызывающего обработать `None`. Невалидный вход или сбой — исключение. Не возвращать `None` из функции с `-> X`, пару `(ok, value)` и коды вроде `-1` из `str.find` (`str.index` бросит `ValueError`).
- **Lambda не присваивать имени, тривиальную — заменять `operator` и `partial`.** Плохо: `area = lambda r: r.w * r.h` → хорошо: `def area(r: Rect) -> float:`. `itemgetter(1)`, `attrgetter("address.city")`, `methodcaller("strip")`, `partial(normalize, "NFC")` вместо `lambda`.
- **Стратегию и хук без состояния передавать функцией, а не классом с одним методом.** `promotion: Callable[[Order], Decimal]`, `sorted(xs, key=len)`. Состояние у хука — класс с `__call__`. Набор стратегий собирать регистрационным декоратором, а не списком, который забудут дополнить. Шаблонный метод — dataclass из `Callable`-шагов, а не иерархия.
- **Помнить: присваивание внутри функции делает имя локальным на всё тело.** `print(count); count = 0` даёт `UnboundLocalError`. Перепривязка во вложенной функции — `nonlocal`; изменяемое состояние замыкания — только в короткой функции, иначе класс.
- **Декоратор оборачивать через `functools.wraps` и типизировать через `ParamSpec`.** Без `wraps` ломаются имя, `help` и интроспекция. Побочные эффекты — внутри обёртки: тело декоратора выполняется при импорте. Обёртка корутины — сама `async def`, иначе замерит лишь создание корутины. Одна обязанность — один декоратор.

  ```python
  def logged[**P, R](func: Callable[P, R]) -> Callable[P, R]:
      @wraps(func)
      def wrapper(*args: P.args, **kwargs: P.kwargs) -> R:
          logger.info("call", extra={"function": func.__qualname__})
          return func(*args, **kwargs)

      return wrapper
  ```

- **Сквозной механизм (повтор, кэш, таймаут) подключать декоратором, а свой декоратор писать, когда он нужен хотя бы в трёх местах.** Цикл повторов внутри бизнес-функции смешивает политику и механизм. Ради трёх строк в двух местах хватит функции. Параметризованный декоратор — со скобками `@retry(times=3)`, параметры keyword-only.
- **Кэшировать через `lru_cache(maxsize=...)` в долгоживущих процессах; на методы `cache` не вешать.** `functools.cache` растёт без предела. `@cache` на методе держит `self` в кэше — утечка памяти; для вычисляемого атрибута — `cached_property`.
- **Вместо цепочки `isinstance` над данными, которые обрабатывают независимые подсистемы, — `functools.singledispatch`.** Регистрировать на ABC и протоколы (`numbers.Integral`), а не на конкретные типы. Если поведение принадлежит самому классу — полиморфный метод.

## 5. Свои типы данных

- **Выбирать вид типа по тому, что он моделирует.**

  | Что моделируешь | Тип |
  |---|---|
  | Синоним, чтобы контракт читался | `type SectionName = str` |
  | Значение с правилом (email, процент) | подкласс `str`/`int`/`Decimal` с проверкой в `__new__` |
  | Значение, прошедшее проверку (очищенный текст, вошедший пользователь) | `NewType` и единственная функция, которая его создаёт |
  | Маленький набор значений без поведения | `Literal["r", "w"]` |
  | Набор вариантов с перебором, проверкой в рантайме или методами | `Enum`; сочетания вариантов — `Flag` |
  | Запись из независимых полей | `@dataclass(frozen=True, slots=True)` |
  | Поля, связанные инвариантом, или изменяемое состояние | класс со скрытыми данными и методами |
  | Взаимоисключающие состояния | `type Payment = Paid \| Refunded \| Failed` и `match` |
  | Чужой JSON, который так и остаётся словарём | `TypedDict` |
  | Отображение с динамическими ключами | `dict` / `Mapping[K, V]` |

- **Значения предметной области делать своими типами, а валидацию — в `__new__` подкласса.** Тогда дальше по коду передаётся только проверенное значение, а сигнатура `Mapping[SectionName, Version]` читается без комментариев.

  ```python
  # плохо
  def send(to: str, subject: str) -> None: ...
  # хорошо
  class Email(str):
      def __new__(cls, value: str) -> Self:
          if "@" not in value:
              raise ValueError(f"invalid email: {value!r}")
          return super().__new__(cls, value)

  def send(to: Email, subject: Subject) -> None: ...
  ```

- **Записи фиксированной формы объявлять `@dataclass(frozen=True, slots=True)`, а не `NamedTuple`, голым `tuple` или словарём.** По `tuple[str, str, int]` и `row[2]` не понять, что внутри; `NamedTuple` можно случайно распаковать или сравнить с кортежем. Статический индекс `row[2]` или ключ `d["name"]` в своём коде — сигнал завести тип. Многие поля — `kw_only=True`; копия с изменением — `dataclasses.replace` (3.13: `copy.replace`). `slots` и `kw_only` — с 3.10.
- **Помнить пределы dataclass.** `frozen` не защищает вложенные объекты: поля делать `tuple`, `frozenset`, другими frozen-классами. Изменяемый default — `field(default_factory=list)`; атрибут класса — `ClassVar[...]`, иначе он станет полем. Аннотации не приводят типы: проверки и приведение — в `__post_init__` с `raise`.
- **Класть в dataclass методы над его данными.** Запись без поведения, вокруг которой по коду размазана логика, — запах: перенести логику в класс. Голая запись оправдана на границе (разбор JSON, DTO) — тогда её не мутировать.
- **Для полей, связанных инвариантом, писать класс, проверяющий инвариант в конструкторе и в каждом мутаторе.** Объект с нарушенным инвариантом не должен существовать. Данные — в `_`-атрибутах, наружу — копия или неизменяемое представление (`tuple(self._items)`, `MappingProxyType(self._index)`). Проверка — `raise ValueError`, не `assert`: его снимает `-O`.
- **Статический набор вариантов делать `Enum` или `Literal`, а не строками и константами.** `Literal` проще — брать его, если не нужны перебор, проверка в рантайме и методы. `Enum` не делать из наборов, известных только в рантайме (из БД, конфига). Значения не важны — `auto()`. Несколько вариантов сразу — `Flag` (`Allergen.FISH | Allergen.NUTS`), а не `set[Enum]`.
- **`IntEnum`, `IntFlag` и `StrEnum` брать только для совместимости с внешним форматом.** Они неявно равны числам и строкам: `Volume.CUP == Weight.OUNCE` при одинаковом значении. Обычно — `Enum` и явный `.value`. Если строковое перечисление нужно — `StrEnum` (3.11), а не `class X(str, Enum)`.
- **Взаимоисключающие состояния разносить по разным типам, а не держать флагами одного класса.** Плохо: `Order(paid: bool, refunded: bool, error_code: int | None)` с недопустимыми сочетаниями → хорошо: `type OrderState = Paid | Refunded | Failed`. Обработка — `match` с `case _: assert_never(state)` (3.11): тайпчекер потребует ветку для нового варианта.
- **Помечать константы модуля `Final`.** `MAX_RETRIES: Final = 5` — тайпчекер поймает переприсваивание; мутацию объекта `Final` не запрещает. Связанные константы выражать друг через друга: `SECONDS_PER_WEEK: Final = 7 * SECONDS_PER_DAY`.
- **Внешние данные (конфиг, ответ API, строку БД) проверять при загрузке и сразу разбирать в свой тип.** `TypedDict` в рантайме — обычный `dict`: `config: Config = json.loads(raw)` проходит тайпчекер, ничего не проверив. Если в проекте pydantic — описывать ограничения в типах полей; он по умолчанию приводит `"123"` к `123`, где это недопустимо — строгий режим.

## 6. Классы и модель данных

- **Реализовывать протоколы языка, а не придумывать свои методы.** `__len__` и `__getitem__` дают `len`, срезы, обход, `in`, `sorted`; `__contains__` превращает `0 <= c.x < grid.width and ...` в `if c in grid:`. Не `equals()`, `size()`, `is_greater_than()`, а `__eq__`, `__len__`, `__lt__`. Dunder-методы не вызывать напрямую: `len(x)`, `next(it)`, а не `x.__len__()`.
- **Писать `__repr__` в виде вызова конструктора и без секретов.** `f"{type(self).__qualname__}({self.amount!r}, {self.currency!r})"` — корректно наследуется. Repr попадает в логи при падении: пароли и токены не выводить. `repr` не должен бросать исключений; dataclass генерирует его сам.
- **`__eq__` делать консервативным, `__hash__` — по тем же полям.** Для чужого типа возвращать `NotImplemented`, иначе `Money(5) == 5` или `Vector(1, 2) == [1, 2]` окажутся истинны. `__eq__` без `__hash__` делает объект нехешируемым. Порядок — `@dataclass(order=True)` или `functools.total_ordering` с одним `__lt__`.
- **В операторах для несовместимого операнда возвращать `NotImplemented`, а не бросать исключение.** Тогда Python попробует `__radd__` второго операнда. Недопустимое значение подходящего типа — исключение. `a + b` не меняет операнды; `__iadd__` — только у изменяемых классов, с `return self`.
- **В `__init__` приводить и копировать аргументы и не делать работы.** `self._items = tuple(items)`: ошибка всплывёт при создании, а не в другом методе. Последовательность принимает один iterable, а не `*args`. Все атрибуты заводить в `__init__`. Зависимости — параметрами, а не `self._client = HttpClient()` внутри. `__init__` не бывает корутиной: асинхронную подготовку — в фабрику.
- **Альтернативный конструктор писать `@classmethod`, возвращающим `cls(...)`.** `Config.from_file(path)` работает и в подклассах.
- **Начинать с публичного атрибута, проверку добавлять через `@property` без смены API.** Не писать `get_x()`/`set_x()`. Свойство — дешёвый запрос без побочных эффектов: I/O, долгие вычисления и операции с аргументами — методы. Производное значение — свойство без сеттера: `obj.total = 1` упадёт сразу. Внутри свойства читать `self._x`, а не само свойство, — иначе рекурсия; в `__init__` присваивать через свойство, чтобы проверка работала и при создании.
- **Внутреннее помечать одним подчёркиванием `_x`, а не `__x`.** `__x` — name mangling против конфликтов с чужими подклассами, а не защита, и он ломает подклассы при перестройке иерархии. Много `_`-методов в классе — признак лишних обязанностей.
- **Наследовать только при взаимозаменяемости, переиспользовать код композицией.** Не наследовать доменный класс от `dict` ради `obj[key]`: он получит `pop`, `clear` и ложное «является словарём» — держать `self._data` и реализовать нужные dunder-методы. Не делать базовый класс под единственную реализацию. Больше 3–4 уровней — признак лишнего наследования.
- **Свою коллекцию наследовать от `collections.abc` или `UserDict`/`UserList`, а не от `dict`/`list`/`str`.** C-методы `dict` (`get`, `update`, `__init__`) не вызывают переопределённые `__getitem__`/`__setitem__`. `MutableMapping`, `Sequence`, `Set` потребуют недостающие методы и дадут остальные бесплатно.
- **Переопределение помечать `@override` (3.12) и не менять в нём контракт.** Не усиливать проверки аргументов, не пропускать обязательную часть, не бросать исключений, которых нет у базы, — особенно `NotImplementedError`. Ошибку тайпчекера о несовместимом переопределении исправлять, а не глушить `# type: ignore`. Родителя вызывать `super().__init__()` без аргументов.
- **Множественное наследование — только с миксинами без состояния.** Миксин — одно поведение, без `__init__` и атрибутов, суффикс `Mixin`, первым в списке баз, каждый метод вызывает `super()`: `class UpperDict(UpperCaseMixin, UserDict)`. Миксин ради одного метода в одном классе заменить декоратором класса или композицией.
- **Не писать класс там, где хватает функции или модуля.** Класс ради одного вызова — функция; класс из одних `@staticmethod` — модуль. Класс нужен, когда несколько функций работают с одной структурой данных. Помощник, нужный только одному классу, держать внутри него (метод, `ClassVar`), общий для нескольких — на уровне модуля.
- **Единственный экземпляр создавать объектом модуля, а не синглтоном.** Модуль импортируется один раз — это и есть «общеизвестный объект».
- **`__del__` не писать.** `del` удаляет ссылку, а не объект; очистка — `with`, колбэк при сборке — `weakref.finalize`, реестры экземпляров — `WeakValueDictionary`.
- **Реализуя `__getattr__`, реализовать и `__setattr__` и бросать `AttributeError`.** `__getattr__` вызывается только для отсутствующих атрибутов: без `__setattr__` присваивание создаст атрибут, затеняющий вычисляемый.
- **Дескриптор писать только для логики атрибутов, повторённой хотя бы трижды, обычно во внутреннем API или библиотеке.** Меньше повторов — `@property`. Имя — из `__set_name__`, значение — в `instance.__dict__[self._name]`: атрибуты самого дескриптора общие для всех экземпляров. При `instance is None` `__get__` возвращает сам дескриптор.
- **Метаклассы не писать.** Проверка и регистрация подклассов — `__init_subclass__` с вызовом `super().__init_subclass__()`; изменение класса — декоратор класса. Метаклассы не компонуются и нужны только фреймворкам.

## 7. Аннотации и тайпчекер

- **Аннотировать все параметры и возвращаемые значения и держать тайпчекер строгим.** Аннотация возврата избавляет читателя от обхода всех `return`. Тестам и функциям без значения — `-> None`. Конфиг `mypy --strict` или pyright strict — в репозитории, с `warn_unused_ignores`. После смены сигнатур запускать тайпчекер проекта. Очевидные локальные переменные (`count = 0`) не аннотировать; пустые коллекции — аннотировать.
- **Параметры, возвращаемые значения и атрибуты аннотировать минимальной абстрактной коллекцией, конкретную создавать в значении.** `Iterable` — один проход, `Collection` — проходы и `len`, `Sequence` — индексы, `Mapping` — чтение; изменяемые — `MutableSequence`, `MutableMapping`. `dict[str, int]` не примет `UserDict` и `ChainMap`, а `Mapping[str, int]` примет. Всегда указывать тип элементов: голый `list` — это `list[Any]`.

  ```python
  # плохо
  def group(orders: list) -> dict: ...
  # хорошо
  def group(orders: Iterable[Order]) -> Mapping[CustomerId, Sequence[Order]]:
      grouped: defaultdict[CustomerId, list[Order]] = defaultdict(list)
      ...
  ```

- **Не принимать `Iterable[str]` или `Sequence[str]` там, где вероятна голая строка.** `str` — тоже последовательность строк: `notify("user@x")` вместо `notify(["user@x"])` пройдёт тайпчекер и разошлёт письма по символам. Сужать тип или проверять явно.
- **Писать `X | None` везде, где возможен `None`, и различать «пусто» и «нет».** `list[Item] | None`: пустой список — данных нет, `None` — результата нет.
- **Где тип не важен — `object`, а не `Any`.** `object` принимает всё и разрешает минимум операций, `Any` выключает проверку. `Any` — только чтобы намеренно отключить проверку. Длинный `Union` — лишняя ветка у каждого вызывающего; разросшийся `Union` в параметрах обычно значит, что вход надо привести к одному типу.
- **Сложный вложенный тип называть псевдонимом с доменным смыслом.** `type Routing = Mapping[Region, Sequence[Warehouse]]` (3.12; раньше — `Routing: TypeAlias = ...`). Дженерик-псевдоним убирает повтор: `type Response[T] = T | ApiError`.
- **Зависимость или утиный тип в параметре описывать `Protocol`, а не `Union` известных классов или общей базой.** Реализациям ничего не нужно наследовать. Протокол — узкий (1–2 метода), объявлен рядом с кодом, который его использует. Наследование от ABC — когда база даёт поведение, которое подтип обязан сохранить.

  ```python
  class Notifier(Protocol):
      def send(self, message: Message) -> None: ...

  def close_order(order: Order, notifier: Notifier) -> None: ...
  ```

- **Составной протокол явно наследовать от `Protocol`; помнить пределы `@runtime_checkable`.** `class Entry(Splittable, Shareable, Protocol): pass` — без `Protocol` в базах это обычный класс. `isinstance` с runtime-протоколом проверяет только наличие атрибутов, а не сигнатуры.
- **Тип, зависящий от аргумента, выражать параметром типа или `@overload`, а не `Union`.** `def first[T](items: Sequence[T]) -> T` (3.12; раньше — `TypeVar`). Граница сохраняет точный тип: `def top[T: SupportsLessThan](xs: Iterable[T], n: int) -> Sequence[T]`, а не `-> Sequence[SupportsLessThan]`. Метод, возвращающий свой экземпляр, — `-> Self` (3.11).
- **Помнить, что изменяемые коллекции инвариантны.** `list[int]` не передать в параметр `list[float]`; принимать `Sequence[float]` — она ковариантна. Где ждут `Callable[[float], None]`, не подойдёт `Callable[[int], None]`.
- **Тело функции использует только операции объявленного типа.** Если функция вызывает `.quack()`, аннотация `Bird` её не описывает — нужен протокол. С `Sequence` нельзя `x * 2`, с `Iterable` — `len(x)`.
- **Сужать типы проверками, которые видит тайпчекер.** `isinstance`, `is None`, `match`; своя проверочная функция — `-> TypeIs[str]` (3.13, сужает обе ветки; раньше `TypeGuard`). Исчерпываемость — `assert_never` (3.11). Классы, не рассчитанные на наследование, — `@final`.
- **`TypedDict` — только для данных, которые остаются словарями.** Необязательные ключи — `NotRequired[...]` (3.11), неизменяемые — `ReadOnly[...]` (3.13). Если данные не обязаны оставаться словарём — сразу разбирать в dataclass.
- **Не глушить тайпчекер без причины.** Сначала переписать код: плохо `number = str(number)  # type: ignore` → хорошо: `number_text = str(number)`. Если тайпчекер не может вывести тип — `cast` лучше `Any`; неизбежный игнор — с кодом ошибки и причиной: `# type: ignore[attr-defined]  # стаб библиотеки не знает про X`. Частый `cast` — запах.
- **В docstring не дублировать аннотации.** Тип уже в сигнатуре; docstring — одна фраза о назначении. Ожидаемые исключения в типы не входят — их проверяют тесты.

## 8. Исключения и контекстные менеджеры

- **Держать в `try` только вызов, который бросает ожидаемое исключение.** Продолжение успешного пути — в `else`, очистка — в `finally`, ресурс открывать до `try`. Иначе `except KeyError` поймает и чужой `KeyError` из соседней строки.
- **Ловить конкретные исключения; `except Exception` — только на границе изоляции и с трейсбеком в логе.** Граница — обработчик запроса, задача фоновой очереди, итерация воркера. Без этого опечатка (`NameError`) маскируется под временный сбой. Голый `except:` и `except BaseException` не писать; перехваченный `KeyboardInterrupt` — завершать голым `raise`.

  ```python
  try:
      response = handle(request)
  except Exception:
      logger.exception("request failed", extra={"request_id": request.id})
      response = Response(status=HTTPStatus.INTERNAL_SERVER_ERROR)
  ```

- **Пакету заводить корневое исключение и бросать только его наследников.** `class Error(Exception)` и `class InvoiceNotFoundError(Error)`: вызывающий ловит конкретное, затем `billing.Error`, а новые подклассы ничего не ломают. Имя ошибки — с суффиксом `Error`. Встроенные `ValueError` и `TypeError` из пакета тогда указывают на баг в нём.
- **Чужие исключения переводить в свои через `raise ... from exc`.** `from exc` сохраняет причину в трейсбеке, `from None` её прячет. Контекст без смены типа — `exc.add_note(f"row {i}")` и голый `raise` (3.11). Несколько независимых ошибок — `ExceptionGroup` и `except*` (3.11).
- **Намеренно игнорируемое исключение оформлять `contextlib.suppress(KeyError)`, а не `except: pass`.** Так видно, что пропуск — часть логики. В `suppress` не передавать `Exception`.
- **Различать `TypeError`, `ValueError`, `NotImplemented` и `NotImplementedError`.** Не тот тип — `TypeError`, недопустимое значение верного типа — `ValueError`. Бинарный оператор с чужим операндом возвращает `NotImplemented`; заглушка нереализованного — `raise NotImplementedError`, а не `pass`.
- **`assert` — только для внутренних допущений, не для проверки входа и не для выхода из ветки.** С `-O` assert исчезает: `assert False` вместо `raise` вернёт `None` там, где обещан другой тип. В assert — сообщение с данными: `assert 0 < rating <= MAX_RATING, f"{rating=}"`. `AssertionError` не ловить.
- **Не выходить из `finally` через `return`, `break`, `continue` и не читать `e` после блока `except`.** Выход из `finally` молча глушит исключение (с 3.14 — `SyntaxWarning`). Переменная `except ... as e` удаляется после блока: нужное значение сохранять в переменную, заведённую до `try`.
- **Вместо отладочного `print` — `logging`, логгер модуля — `logging.getLogger(__name__)`.** Сообщение — постоянная строка, значения — в `extra`: `logger.info("order paid", extra={"order_id": order.id})`.
- **Ресурсы и парные операции оборачивать в `with`.** Файл, блокировка, транзакция, резерв, временная смена состояния — всё, что обязано вернуться назад даже при исключении. Если вызывающий обязан помнить про «закрыть» или «откатить» — отдать ему контекстный менеджер, а не пару методов. Несколько менеджеров — в скобках (3.10).
- **Прежде чем писать свой менеджер — искать в `contextlib`.** `suppress`, `closing`, `nullcontext` (менеджер по условию), `ExitStack` (переменное число), `chdir` (3.11, меняет каталог всего процесса).
- **Свой менеджер без состояния писать через `@contextmanager` и оборачивать `yield` в `try/finally`.** Исключение из блока `with` бросается в точке `yield`: без `finally` восстановление не выполнится. Класс с `__enter__`/`__exit__` — когда у менеджера есть своё состояние; `__exit__` возвращает `True` только для намеренно подавленного исключения.

  ```python
  @contextmanager
  def reserved(items: Collection[Item]) -> Iterator[Reservation]:
      reservation = reserve(items)
      try:
          yield reservation
      finally:
          reservation.release()
  ```

## 9. Модули, импорты, пакеты

- **Публичные имена модуля перечислять в `__all__`, по одному на строке, с запятой после последнего.** Внутренние имена модуля — функции, классы, константы, сами модули пакета — помечать `_` даже при заданном `__all__`: читатель видит, что имя внутреннее, прямо в месте использования, а не только в `__all__`. API пакета собирать в `__init__.py` реэкспортом: клиенты импортируют из корня пакета, внутренние модули можно перестраивать. `from x import *` в коде не писать.

  ```python
  __all__ = [
      "Invoice",
      "InvoiceNotFoundError",
      "load_invoice",
  ]
  ```

- **Большой модуль разбивать в пакет, сохраняя старые импорты.** `__init__.py` реэкспортирует имена — вызывающий код не меняется.
- **Не выполнять работу при импорте.** Импорт выполняет весь код верхнего уровня, включая тела декораторов: никаких соединений, чтения файлов и глобальной настройки. Регистрация в реестре декоратором — допустимое исключение. Настройка — явной функцией, вызываемой из точки входа.
- **Циклический импорт разрывать выносом общего кода в модуль ниже по графу зависимостей.** Импорт внутри функции — последнее средство; импорты в конец файла не переносить.
- **Тяжёлый модуль, нужный одной ветке, импортировать лениво.** С 3.15 — `lazy import` в начале модуля; раньше — импорт внутри функции. Время импорта — `python -X importtime`.
- **Не называть свои модули как модули stdlib и зависимостей.** `email.py`, `random.py`, `requests.py` перехватят импорт.
- **Ломающее изменение API вводить через предупреждение об устаревании.** `@warnings.deprecated("use load_invoice()")` (3.13) видят и тайпчекер, и рантайм; раньше — `warnings.warn(..., DeprecationWarning, stacklevel=2)`. Новый параметр получает default, и старое поведение остаётся, пока его не уберут.
- **Метаданные и файлы пакета читать через `importlib.metadata` и `importlib.resources.files()`.** `pkg_resources` с 3.12 в новом venv не установлен.
- **После правки прогонять команды проверки проекта.** Форматтер, линтер и тайпчекер — теми командами и с тем конфигом, что есть в проекте (`ruff format`, `ruff check`, `mypy` и т. п.). Длина строки и порядок импортов — за форматтером, не вручную.

## 10. Потоки и процессы

Для `async`/`await` — `asyncio.md`. Здесь — конкурентность без asyncio.

- **Потоки — для блокирующего I/O, процессы — для вычислений.** Из-за GIL потоки на CPU-задачах не быстрее последовательного кода. Вычисления — `ProcessPoolExecutor` с небольшими входами и выходами. Free-threaded сборка (официально с 3.14) по умолчанию не включена — на неё не рассчитывать.
- **Управлять потоками через executors, а не создавать `Thread` на каждую задачу.** `with ThreadPoolExecutor(max_workers=...) as pool:`; `pool.map` отдаёт результаты в порядке подачи, `submit` + `as_completed` — по готовности. `future.result()` пробрасывает исключение вызывающему, а исключение в голом `Thread` уходит только в stderr.
- **Общее изменяемое состояние между потоками защищать `Lock`.** GIL не делает `counter += 1` атомарным. Проверка и действие (`if key in cache: return cache[key]`) между потоками — гонка; держать их под одной блокировкой. Критическую секцию держать минимальной; метод под замком вызывает другой метод под тем же замком — `RLock`; несколько замков брать всегда в одном порядке.
- **Конвейер между потоками строить на `queue.Queue(maxsize=...)`.** Ограничение размера даёт обратное давление, `task_done`/`join` — ожидание. Остановка потребителей — `queue.shutdown()` (3.13), раньше — сентинел.

## Чек-лист перед сдачей кода

1. Код использует возможности версии из `requires-python` — без устаревших конструкций и без возможностей более новых версий?
2. Все сигнатуры аннотированы, коллекции в аннотациях — абстрактные и с типом элементов, нет `Any` без причины, тайпчекер проекта проходит без новых `# type: ignore`?
3. Значения предметной области — свои типы, записи — frozen dataclass, наборы вариантов — `Enum` или `Literal`, а не строки, кортежи и словари с индексами?
4. Нет изменяемых значений по умолчанию, неявных `None` из `-> X`, двойного прохода по итератору и изменения коллекции во время обхода?
5. Флаги и необязательные параметры — keyword-only, а функции не меняют аргументы молча?
6. Классы реализуют протоколы языка, наследуются только ради подстановки, а свойства дешёвы и без побочных эффектов?
7. Исключения конкретные, чужие переведены в свои через `from`, `except Exception` — только на границе с `logger.exception`?
8. Ресурсы и парные операции — в `with`, свои менеджеры — через `@contextmanager` с `try/finally`?
9. У модулей есть `__all__`, при импорте не выполняется работа, нет циклических импортов?
10. Форматтер, линтер и тайпчекер проекта прогнаны после правки?
