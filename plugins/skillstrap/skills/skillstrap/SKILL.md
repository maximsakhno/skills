# Как собрать скилл по книгам

Скилл ведёт от темы до готового плагина за шесть шагов: уточнить тему → подобрать книги → создать папку для книг → конвертировать книги → законспектировать → собрать скилл и проверить. Шаги 2 и 3 ждут ответа пользователя: не идти дальше без него.

Пути `scripts/…`, `template/…` и `summary-prompt.md` ниже — относительно папки этого скилла.

Готовый плагин устроен так:

```
<name>/
├── .claude-plugin/plugin.json   манифест плагина
├── skills/<name>/SKILL.md       свод правил
├── README.md, LICENSE, .gitignore
├── books/                       книги пользователя, не в git
├── .build/md/                   книги в Markdown, не в git
└── notes/                       конспекты, не в git
```

Если папка плагина уже есть, а в `notes/` лежат конспекты, работа прервалась: продолжить с первого незавершённого шага, а не начинать заново.

## Шаг 1. Уточнить тему

Из запроса нужно понять три вещи. Чего нет в запросе — спросить одним сообщением, остальное не переспрашивать.

- **Границы темы.** «Kubernetes» — это эксплуатация кластера или манифесты, которые пишет разработчик? От границ зависит подбор книг.
- **Что агент должен делать лучше.** Писать код, ревьюить, проектировать, отвечать на вопросы, писать тексты. Это фильтр для книг и конспектов.
- **Имя плагина.** Латиницей в kebab-case: предложить своё, например `k8s-manifests`. Это же имя получит скилл.

Скилл пишется на языке общения с пользователем, если он не попросил другой.

Сформулировать цель скилла одной фразой: «Агент пишет манифесты Kubernetes, которые проходят ревью SRE без замечаний». Цель понадобится субагентам.

## Шаг 2. Подобрать книги

Нужен набор книг, который раскрывает тему с разных сторон и не повторяется.

### Как искать

- **Сначала память, потом интернет.** Набросать кандидатов из памяти, затем проверить и дополнить их через WebSearch: подборки практиков, программы университетских курсов, списки издательств (O'Reilly, Manning, Pragmatic Bookshelf, Addison-Wesley и т. п.). Независимые запросы отправлять в одном ходе.
- **Последнее издание.** Для каждой книги проверить на сайте издательства или магазина, какое издание последнее и когда вышло. Для технических тем убедиться, что книга не устарела относительно текущей версии технологии.
- **Язык оригинала.** Указывать оригинальное название и издание. Перевод — только если пользователь попросил.

### Как отбирать

- **Каждая книга — своя грань темы.** Например: принципы и модель мышления, практика и рецепты, антипаттерны и отказы, устройство изнутри, процесс и командная работа. Из двух книг об одном и том же с одной стороны оставить лучшую.
- **Правила, а не мотивация.** Предпочитать книги, из которых выходят проверяемые правила и примеры.
- **Авторитет.** Автор — практик или исследователь темы, книгу цитируют и рекомендуют специалисты.
- **Объём набора.** В первом раунде предложить 6–10 книг. Скиллу обычно хватает 6–12.

### Как показать

Таблицей, по строке на книгу:

| № | Книга | Издание | Что добавляет | Почему она |
|---|-------|---------|---------------|------------|
| 1 | Brendan Burns et al., «Kubernetes: Up and Running» | 3rd ed., 2022 | основы объектов и манифестов | написана создателями Kubernetes |

Под таблицей одной строкой: какие грани темы набор уже покрывает и каких не хватает. Затем попросить ответить номерами: какие книги взять, какие нет.

### Раунды

Одобренные книги копятся от раунда к раунду. В следующем раунде показывать только новых кандидатов: на место отклонённых и для непокрытых граней. Отклонённые книги больше не предлагать. Раунды идут, пока пользователь не скажет, что книг достаточно.

## Шаг 3. Создать папку для книг

1. **Выбрать папку плагина.** Предложить `<текущая папка>/<name>`, а если текущая папка — репозиторий другого проекта, то папку рядом с ним. Пользователь может назвать свою. Существующие файлы не перезаписывать.
2. **Создать папки и `.gitignore`:**
   ```
   mkdir -p <dir>/books <dir>/notes
   cp template/gitignore <dir>/.gitignore
   ```
3. **Записать список книг** в `<dir>/notes/books.md`: автор, название, издание, год, грань темы. Дальше этот список — источник истины для шагов 4–6.
4. **Попросить пользователя положить книги** в `<dir>/books/` и написать, когда закончит. В сообщении — полный путь к папке, список книг и форматы: EPUB, PDF с текстовым слоем, DOCX, HTML, TXT. FB2, MOBI, AZW3 и DjVu сначала сконвертировать в EPUB или PDF, например через Calibre. Имена файлов любые. В git книги не попадут.

## Шаг 4. Конвертировать книги в Markdown

Субагенты читают книги только в Markdown: конвертировать все книги до их запуска.

1. **Сопоставить файлы со списком.** Если каких-то книг нет или есть лишние файлы, спросить пользователя: дождаться или продолжить без них.
2. **Конвертировать:**
   ```
   python3 scripts/convert_books.py <dir>
   ```
   Скрипт прогоняет каждую книгу через markitdown, переносит длинные строки, чтобы Read их не обрезал, и пишет результат в `<dir>/.build/md/<имя файла>.md`. Уже сконвертированные книги пропускает. Без установленного markitdown запускает его через `uvx`.
3. **Разобрать проблемы.** Строка «МАЛО ТЕКСТА» значит, что PDF — скан без текстового слоя: попросить у пользователя другой файл или исключить книгу. «НЕ ПОДДЕРЖИВАЕТСЯ» и «ОШИБКА» — попросить файл в другом формате.
4. **Проверить качество.** Просмотреть начало и середину каждого `.md`: текст читается, нет сплошного мусора из символов. Если мусор есть, обработать как скан.

## Шаг 5. Законспектировать книги

1. **Запускать по субагенту на книгу, по одному.** Следующего субагента — только после того, как предыдущий закончил и его конспект проверен. Книги, у которых уже есть `notes/<slug>.md`, пропустить.
2. **Промпт субагента** — `summary-prompt.md` с подставленными значениями:
   - `{{BOOK}}` — автор, название, издание, год;
   - `{{TEXT_PATH}}` и `{{LINES}}` — путь к `.md` книги и число строк из вывода скрипта;
   - `{{NOTES_PATH}}` — `<dir>/notes/<slug>.md`, где slug — фамилия автора и ключевые слова названия латиницей: `burns-kubernetes-up-and-running`;
   - `{{TOPIC}}`, `{{GOAL}}`, `{{LANGUAGE}}` — из шага 1;
   - `{{FACET}}` — грань темы из таблицы шага 2.
3. **Проверить конспект.** Файл есть и в нужном формате. Если субагент упал или конспекта нет, перезапустить его для этой книги.
4. **Сообщить пользователю** одной строкой после каждой книги: сколько правил и были ли проблемы с текстом. Когда законспектированы все книги, сразу переходить к шагу 6; конспекты пользователь может прочитать в `<dir>/notes/`.

## Шаг 6. Собрать скилл

### Свести правила

Прочитать все конспекты и составить единый набор правил.

- **Группировать по работе агента, а не по книгам.** Разделы — этапы или стороны задачи в порядке, в каком агент с ними сталкивается. Например, для письма: до текста → начало → структура → предложения → слова → редактура.
- **Объединять дубли.** Одно правило — одна формулировка и лучший пример из всех книг.
- **Разрешать противоречия.** Выбрать один вариант — тот, что лучше служит цели скилла. Не писать «одни авторы считают…». Выбор запомнить для отчёта пользователю.
- **Убирать то, что агент и так делает.** Общий совет без проверяемого действия («пишите понятный код») не меняет поведение агента и только тратит контекст.
- **Не добавлять правил, которых нет в конспектах.** Свои знания — только для примеров, приближенных к задачам агента.
- **Переформулировать под агента.** Правило для человека («перечитайте текст вслух») превратить в то, что агент может сделать, или выбросить.

### Создать файлы плагина

```
python3 scripts/scaffold.py --dir <dir> --name <name> --author "<автор>" \
  --description "<что плагин делает агенту, одной фразой>" [--repository <url>]
```

Автор — из `git config user.name` или как назовёт пользователь. Репозиторий — только если пользователь его назвал. Скрипт создаёт `plugin.json`, `LICENSE` и папку скилла. Существующие файлы он не трогает.

### Написать `skills/<name>/SKILL.md`

- **Frontmatter.** `name` — имя плагина. `description` — что в скилле и когда его загружать, с типичными задачами и словами пользователя: «Используй, когда пишешь, правишь или ревьюишь манифесты Kubernetes, Helm-чарты, …». От описания зависит, загрузит ли агент скилл.
- **Заголовок и вступление.** H1 — о чём свод. Абзац: область применения, из скольких книг сведены правила, главный принцип в 1–2 фразах.
- **Разделы.** `## N. Название по сути`, 5–12 разделов.
- **Правило — пункт списка.** `**Действие глаголом в неопределённой форме.** Почему и когда, 1–3 предложения. Плохо: … → хорошо: …`. Примеры брать из практики агента: код, команды, ответы.
- **Чек-лист в конце.** 5–10 вопросов для самопроверки перед сдачей работы.
- **Без ссылок на книги в тексте.** Источники — в README.
- **Объём.** Ориентир — 15–30 тысяч символов. Если выходит больше 40 тысяч, оставить в `SKILL.md` основное, а подтемы вынести в отдельные файлы рядом. В `SKILL.md` указать, когда читать каждый из них.

### Написать `README.md`

Разделы по порядку:

1. **Название и суть.** Одна-две фразы: что плагин меняет в работе агента.
2. **Пример.** Типичная задача: ответ агента без плагина и с ним.
3. **Установка.** Если пользователь назвал маркетплейс — команды `/plugin marketplace add <маркетплейс>` и `/plugin install <name>@<маркетплейс>`. Иначе — запуск из папки: `claude --plugin-dir <dir>`.
4. **Как правила попадают к агенту.** Агент загружает скилл сам, когда задача подходит под его описание. Вызвать вручную: `/<name>:<name>`.
5. **Ограничения.** Где правила не действуют; что правила — инструкция, а не проверка.
6. **Как изменить правила.** Какой файл править и как проверить плагин.
7. **Откуда правила.** Список книг: автор, «название». Одна фраза о том, что где авторы расходились, выбран один вариант.
8. **Лицензия.**

### Проверить и сдать

1. Проверить плагин: `claude plugin validate <dir>`.
2. Убедиться, что в файлах не осталось подстановок: `grep -rn '{{' <dir> --exclude-dir=books --exclude-dir=notes --exclude-dir=.build`.
3. Перечитать `SKILL.md` как агент без контекста: каждое правило понятно без книг, у абстрактных правил есть примеры, разделы не повторяют друг друга.
4. Сообщить пользователю:
   - путь к плагину, число разделов и правил;
   - какие противоречия между книгами были и какой вариант выбран;
   - как попробовать: `claude --plugin-dir <dir>`.

Не коммитить и не пушить без просьбы пользователя: предложить это одной строкой.
