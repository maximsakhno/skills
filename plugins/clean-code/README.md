# clean-code

Плагин для Claude Code: агент пишет, ревьюит и рефакторит код так, чтобы другой разработчик понимал его с первого прочтения и менял без страха. Правила не привязаны к языку. Они касаются имён, деления на модули, классы и функции, одной ответственности, запахов кода, работы с кодом без тестов и выбора решения по размеру задачи — когда SOLID и паттерны оправданы, а когда лишние.

## Пример

Задача: «Добавь оплату через СБП к оплате картой».

Без плагина агент часто строит архитектуру заранее: интерфейс `PaymentStrategy`, фабрику, реестр стратегий и конфигурацию — ради второго способа оплаты, который отличается тремя строками. Или наоборот, копирует функцию оплаты картой и правит копию.

С плагином агент смотрит, что именно различается. Общее — проверка заказа и запись платежа — остаётся в одном месте. Различие — вызов платёжного шлюза — уходит за адаптер в терминах приложения. Стратегию агент вводит, только если вариантов станет больше или они начнут меняться независимо. Попутный рефакторинг он отделяет от новой функциональности и не выходит за рамки задачи.

## Установка

```
/plugin marketplace add maximsakhno/skills
/plugin install clean-code@maximsakhno
```

С Claude Code 2.1.275 и новее хватит одной команды:

```
/plugin install clean-code --marketplace maximsakhno/skills
```

## Как правила попадают к агенту

Агент загружает скилл сам, когда задача подходит под его описание: написать, изменить, отрефакторить или поревьюить код, выбрать имена, решить, выносить ли функцию или вводить ли абстракцию. Вызвать вручную: `/clean-code:clean-code`.

Скилл состоит из трёх файлов:

- `skills/clean-code/SKILL.md` — основной свод: 11 разделов и чек-лист.
- `skills/clean-code/smells.md` — каталог запахов кода с лекарствами, агент читает его перед ревью и рефакторингом.
- `skills/clean-code/legacy.md` — приёмы изменения кода без тестов.

## Ограничения

- Правила — инструкция агенту, а не проверка. Они не заменяют линтер, тесты и ревью человеком.
- Правила общие для всех языков. Идиомы конкретного языка и фреймворка — в отдельных скиллах; конвенции проекта, его линтер и `CLAUDE.md` важнее этого свода.
- Архитектура уровня системы — микросервисы, очереди, развёртывание — не покрыта. Тестирование затронуто только там, где оно нужно для безопасного изменения кода.
- Часть источников была доступна не полностью, поэтому некоторые темы раскрыты слабее. Например, о том, когда не дробить код и когда наводить порядок, правил меньше, чем могло бы быть.

## Как изменить правила

Править `skills/clean-code/SKILL.md`, `smells.md` или `legacy.md`. Правило записывается пунктом: действие глаголом в неопределённой форме, причина в 1–3 предложениях, пример «плохо → хорошо». После правки проверить плагин:

```
claude plugin validate /path/to/clean-code
```

и попробовать на задаче через `claude --plugin-dir /path/to/clean-code`.

## Откуда правила

- Robert C. Martin, «Clean Code» (2nd ed., 2025)
- Mark Seemann, «Code That Fits in Your Head»
- David Thomas, Andrew Hunt, «The Pragmatic Programmer» (20th Anniversary ed.)
- Martin Fowler, «Refactoring»
- Michael Feathers, «Working Effectively with Legacy Code»
- Vlad Khononov, «Balancing Coupling in Software Design»
- John Ousterhout, «A Philosophy of Software Design»
- Kent Beck, «Tidy First?»

Где авторы расходились, в своде выбран один вариант — тот, что лучше служит понятности и простоте изменения кода.
